# 任務｜XK 一頁式網站建置服務廣告頁

請在獨立專案 `xk-campaign-website-design`，使用 Next.js 與 TypeScript 實作繁體中文、手機優先的一頁式廣告頁。首頁為 `/`，可從 repo 根目錄獨立安裝、啟動及建置。完成後實際驗證並交付本機預覽。本次不部署、不推送遠端、不修改 `xk-website` 或公司文件庫。

## 1. 服務、訪客與頁面目標

廣告主為 Xplore Kaleidoscope (XK)，本頁只推廣 R01 網站建置中的「一頁式網站建置服務」。

主要訪客是從 LINE、社群貼文、電子名片或朋友介紹進來的店家老闆、中小企業窗口與活動承辦人。他們知道自己的生意需要什麼，但不一定知道怎麼寫網站規格。

訪客完成本頁後，應能帶走一段可直接用來討論的建站需求，寫清楚四件事：替誰做、給誰看、希望訪客做什麼、手上有哪些素材。以「產生並複製需求摘要」作為本版的主要完成動作。

## 2. 參考來源與工程基準

- XK 官網：https://xk2022.github.io/xk-website/
- 官網程式與已實作路由：https://github.com/xk2022/xk-website
- 公司文件與品牌素材：https://github.com/xk2022/xplore-kaleidoscope
- 參考公司庫 `doc/01_business-plan/week-03/` 的前端架構與 GitHub 開發流程，以及 `assets/brand/logo/` 的正式 Logo 03。這些 repo 僅供讀取。
- 先讀取目標專案既有 README.md、AGENTS.md、package.json 與 lockfile。空 repo 使用 Node.js 24.x、npm、Next.js App Router、React、TypeScript、Tailwind CSS；加入值為 `24` 的 `.nvmrc` 並保留 `package-lock.json`。需要 UI 元件或圖示時優先沿用 shadcn/ui、Lucide。
- 靜態文案與版面使用 Server Components。情境選取、表單與剪貼簿操作使用 Client Components。品牌資訊、情境、外部網址與案例公開狀態集中於 `src/config/campaign.ts`。

## 3. 頁面內容與文案

### 首屏

顯示 XK 正式 Logo 03，以及服務名稱「一頁式網站建置」。

主標：「讓客人看懂你的服務，知道下一步怎麼做。」
副標：「從看菜單、找門市，到詢價、報名，把客人最常問的事，整理成手機上就能用的一頁。」

- 主按鈕「整理我的建站需求」前往 `#brief`。
- 次按鈕「看看適合我的情境」前往 `#scenarios`。
- 手機首屏可直接操作兩個入口。主視覺可用自行設計的手機頁面示意，讓訪客看見「導航」「詢價」等具體動作。若使用示意畫面，標明「介面示意」。

### 適合我的情境 `#scenarios`

呈現三種用途，每種只寫一個客戶問題與一個可操作的例子：

| 情境 | 訪客常問的問題 | 網站可提供的動作 |
| --- | --- | --- |
| 在地店家 | 「你在哪裡？有什麼可以先看？」 | 看餐點或服務、導航到店、整理預留或團訂訊息 |
| 製造與企業服務 | 「我知道用途，還不知道該問哪種規格。」 | 看加工樣本，帶入類別並整理詢價需求 |
| 品牌與活動推廣 | 「這個方案適合我嗎？我要怎麼參加或詢問？」 | 選送禮情境、看活動資訊，前往已確認的洽詢或報名入口 |

每種情境提供「用這個情境開始」。點選後前往表單並預選情境，只更新情境欄，保留手動輸入的品牌、受眾、目標與素材。

可用「三月手工湯包、宏能興業、宏家燕窩、御品園港式燒臘」作為內容規劃參考，不必在畫面硬放四張作品卡。若要出現具名作品或截圖，請核對狀態與素材來源，標明「規劃中」或「自主展示」。只有已公開且能實際開啟的案例才顯示「查看展示」。不宣稱這些品牌是付費客戶。

### 合作方式

用三步說清楚：
1. 整理需求：確認對象、訪客動作與現有素材。
2. 確認頁面：討論文案、版面、互動以及要連往哪個管道。
3. 預覽與驗收：在手機和桌面實際操作，核對內容與連結。

本頁不自行刊登方案價格、固定交期、成效數字、折扣或客戶評價。

## 4. 建站需求整理工具 `#brief`

標題：「先整理你的第一頁。」
提示：「填完就能複製需求摘要。內容只在這個頁面整理，不會自動寄給 XK。」

| 欄位 | 行為 |
| --- | --- |
| 品牌或專案名稱 | 必填，自由輸入；還沒取名可填暫名。 |
| 使用情境 | 選填，選項為在地店家、製造與企業服務、品牌與活動推廣、其他。 |
| 想給誰看 | 必填，例如「正在比較加工廠的採購」；可直接用白話描述。 |
| 希望訪客做什麼 | 必填，選一個主要動作，例如導航、詢價、報名、整理預留需求或其他。選其他時可自行填寫。 |
| 已有素材 | 可複選 Logo、照片、文案、社群或既有網站，以及「尚未準備」。「尚未準備」和已有素材互斥。 |
| 想補充的事 | 選填，例如既有頁面最常被客人問到的問題。 |

- 提供「帶入示範資料」，使用虛構品牌與完整範例。只有主動按此按鈕才覆寫草稿。不要求姓名、電話或信箱。
- 按「產生需求摘要」後，檢查必填欄位及純空白文字；錯誤顯示於欄位旁，焦點移到第一個錯誤欄位。
- 摘要採可直接轉貼的自然繁體中文。例如：「我想替山角工作室做一頁式網站，主要給正在找客製木作的店主看。最希望訪客看完後提出詢價。目前已有 Logo 和作品照片。」
- 提供「返回修改」與「複製需求摘要」。再次產生時須反映最新值；不得複製上一版內容。
- 剪貼簿寫入成功才顯示「已複製，可自行貼給 XK」。若被拒絕，保留可手動選取的全文並告知使用者。
- 表單資料只放在當頁記憶體，重新整理即清空。不要建立寄信 API、後台、追蹤像素，或將草稿寫入網址、分析事件及瀏覽器儲存空間。

## 5. 官網導流與品牌呈現

- 摘要旁放「查看 XK 聯絡資訊」，連至 `https://xk2022.github.io/xk-website/contact/`。直接連到官網，不把表單內容附加在 URL。
- 頁尾提供「XK 官網」「完整服務」「技術作品集」，分別連至 Pages 基底 `/xk-website/`、`/xk-website/services/`、`/xk-website/portfolio/` 的完整絕對網址。不要把官網路徑誤寫成本廣告頁的內部路由。
- 實際核對目的頁面；若外部連線受限，在 README 記錄哪些僅核對了來源碼、哪些已用瀏覽器開啟。不自行新增 LINE、Email 或預約連結。
- 沿用 XK 正式 Logo 03、品牌色、字型與可見焦點樣式。使用語意化 HTML，圖片有合適的替代文字，鍵盤能完成整段互動。
- 設定 `lang="zh-Hant"`、頁面標題「一頁式網站建置｜Xplore Kaleidoscope（XK）」、description 與 Open Graph。展示版沿用 `noindex, nofollow`；正式廣告頁網址核定後再設定自己的 canonical。

## 6. 完成條件

1. 以瀏覽器驗證 375、768、1024、1440px。確認行動按鈕容易找到、無水平溢位，長品牌名與多行摘要能換行。
2. 測試三個情境入口與直接填表兩種路徑。先填內容再切換情境，確認草稿保留。測試「其他」動作、「尚未準備」互斥、空白必填與錯誤焦點。
3. 走完「帶入示範 → 產生摘要 → 返回修改主要動作 → 再次產生 → 複製」，比對最新內容。另測剪貼簿被拒時的手動複製，以及重新整理後清空。
4. 在 Node.js 24 下執行 `npm ci`、`npm run lint`、`npm run typecheck`、`npm test`、`npm run build`。新專案請提供對應 scripts；測試至少涵蓋情境切換保留草稿、素材互斥與摘要更新。
5. 交付完整原始碼與 README，列出主要修改檔案、品牌與情境資料位置、外部連結核對結果、各項命令與瀏覽器驗收結果。實際啟動首頁後，以繁體中文提供可直接複製的本機啟動指令、預覽網址和連接埠。未驗證項目標明原因。
